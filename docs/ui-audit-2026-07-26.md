# UI / design audit — 2026-07-26

Same method as `perf-audit-2026-07-26.md`: measure first, judge second. Screens
were inspected live at 1440×900, 900×1500 and 375×812 with the auth gate and the
dashboard's data layer temporarily stubbed (both reverted).

## What is genuinely good

Worth stating plainly, because it constrains what should change.

- **Token discipline is excellent.** Zero hardcoded hex values across ~5,500
  lines of TSX, and exactly one stray Tailwind palette colour (`text-amber-500`).
  Almost every surface goes through `--color-*` tokens.
- **Dark mode is better engineered than light mode** — it passes WCAG AA on all
  11 measured token pairs, and the inverted teal ramp is a deliberate, correct
  choice rather than a naive filter.
- **The login screen is well composed** at desktop: the split layout, the
  artwork panel, the rotating quotes with the animated gradient border. It has a
  point of view.
- **Error and empty states exist and are designed** — the dashboard's failure
  state has an icon, a title, an explanation and a retry action. Most apps at
  this stage have a blank screen.
- `formatMoney` already uses non-breaking spaces as thousands separators, and
  the body sets `font-feature-settings: "tnum"` for tabular figures. Someone was
  thinking about money typography.

## Measured defects

### Contrast — light mode fails, dark mode passes

Computed WCAG ratios for every token pair. Light mode fails **5 of 11**; dark
mode fails **0 of 11**. All failures are on text rendered at `text-xs` (12px),
which requires 4.5:1.

| Pair | Ratio | Verdict |
|---|---|---|
| positive `#16a34a` on white | 3.30:1 | fail |
| positive on positive-bg (badge) | 3.15:1 | fail |
| negative on negative-bg (badge) | 4.41:1 | fail (marginal) |
| terracotta-600 `#ea580c` on white | 3.56:1 | fail |
| terracotta-600 on terracotta-100 | 3.11:1 | fail |

These are not hypothetical — they are the "64% des contributions" and "Fonds
disponibles" captions on the dashboard's primary KPI row.

### Type and radius have no scale

- `text-xs` **246** uses, `text-sm` 88, `text-lg` 21, `text-base` 13, `text-xl`
  7, `text-2xl` 5, `text-3xl` 1. 12px is the de facto body size of a financial
  app read on phones.
- **7 radius values** in use (`rounded-md` 62, `full` 34, `lg` 22, `sm` 16, `xl`
  14, `none` 5, `2xl` 2) while `--radius: 0.5rem` is defined and drives none of
  them.
- `StatCard` renders the same KPI number at `text-2xl` in one variant and
  `text-lg` in the other.

### Money wraps mid-currency

Every KPI card renders `75 000 000 F` and wraps `CFA` onto a second line, at
every viewport. `formatMoney` joins amount to currency with ` `, but the
default currency string `"F CFA"` contains a **regular** space. One-character fix.

### The font strategy costs more than the API

`index.html` loads Manrope + Inter from `fonts.googleapis.com` via a
render-blocking stylesheet. Measured from Abidjan:

- the CSS alone: **0.56–0.76 s** (23 KB)
- each woff2: **~0.5 s** on a *second* origin (`fonts.gstatic.com`)

That is two extra DNS+TLS handshakes before text paints — more blocking time
than the entire data-fetch budget.

### Images

- `login-artwork.png` is **591 KB** and is actually a **JPEG** (1024×1024, 300
  DPI) with a `.png` extension.
- `empty-state.png` is **402 KB**.
- The artwork panel is `hidden w-1/2 md:flex`. `display:none` does **not**
  prevent the fetch — confirmed in the network log, mobile downloads 591 KB it
  never renders.

### Theme flash

`theme.tsx` reads the stored theme synchronously (correct) but applies the class
in a `useEffect`, and `index.html` has no bootstrap script. Every dark-mode user
sees a flash of light theme on every load.

### Login form ships a hardcoded admin address

`useState("admin@college.ci")` prefills the production login form.

### Mock data wears the same clothes as real data

"420 Élèves", "18 Enseignants", "12 classes · 35 él./cl." render as full donut
and bar panels with the same visual authority as the real money beside them.
They are hardcoded mock values — no students/teachers/classes tables exist. The
sidebar also places the entirely-mock **ACADÉMIQUE** section *above* **FINANCES**,
which is the part that works.

### Chart legibility

"Évolution des flux financiers" plots two cumulative series that overlap almost
exactly, with no y-axis, no gridline values and no scale. It occupies a large
block and communicates close to nothing.

## Ranked by consequence

1. Contrast failures + 12px body — legibility, on every screen, for every user.
2. Fonts + images — ~1.5 s of avoidable blocking and ~1 MB of avoidable payload.
3. Money wrapping — visible on the most important number in the app, one char.
4. Mock-vs-real ambiguity — a trust problem, not a cosmetic one.
5. Type/radius scale — the systemic fix that prevents recurrence.
